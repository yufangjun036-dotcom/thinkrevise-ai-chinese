# ThinkRevise AI 隐私、安全与费用控制

更新日期：2026-09-08

## 已在代码中实施

- API 密钥只从服务端环境变量读取，`.env.local` 不进入 Git。
- 三个 AI 接口都在读取完整 JSON 前执行字节级请求体上限。
- 默认每个访客每分钟最多 5 个 AI 请求、每天最多 20 个，同时最多 1 个。
- 默认全站每天最多 100 个 AI 请求、同时最多 3 个。
- 超限响应带有 `Retry-After`、中文恢复说明和 `Cache-Control: no-store`。
- OpenAI 请求使用 `store: false`；应用本身不建立文章数据库。
- 刷新恢复只使用当前标签页的 `sessionStorage`，主动重新开始会清除。
- 日志只记录请求阶段、模式、耗时、令牌数量和简短错误类别，不记录完整文章或密钥。
- 所有学习者输入在提示词中都被声明为待分析数据，而不是可执行指令。
- 页面发送防点击劫持、禁止 MIME 猜测、无来源泄露和关闭摄像头／麦克风／定位权限等响应头。

默认值可以通过 `.env.example` 中的环境变量调整。公开试用初期不建议直接提高上限。

## 内容安全决定

当前版本不额外调用内容审核接口。原因是产品只处理文字写作，课程文章可能合理讨论暴力、歧视、心理健康或其他敏感社会议题；简单关键词阻断容易误伤正常学术文本，并增加延迟和调用次数。当前先使用长度、频率、并发、提示注入边界和模型服务商自身政策保护。若公开试用出现真实滥用证据，再根据案例加入可解释、可申诉且不影响正常学术讨论的审核流程。

## 公开部署前必须完成的外部设置

1. 为生产环境建立独立 OpenAI Project 和独立 API Key，不复用本地开发密钥。
2. 在 OpenAI Platform 为该项目配置适合试用规模的硬性消费上限和分级消费提醒；官方 API 目前同时提供项目级 spend limit 与 spend alert。不要只依赖账户余额或应用内计数。
3. 保持自动充值关闭，或为任何自动充值设置用户能够接受的绝对上限。
4. 在部署平台仅通过 Secret／Environment Variables 配置密钥，检查构建日志和客户端文件中没有密钥。
5. 如果部署平台会自动扩展为多个实例，把当前内存计数器替换为共享的持久化限流存储，或启用平台级防火墙／限流。当前内存保护适合本地、单实例和小规模试用，但不能被描述为抵御分布式攻击的最终方案。
6. 发布后先用隐私窗口完成一次真实访客测试，再小范围邀请同伴。

## 事件处理

- 额度异常下降：先暂停部署或清除生产密钥，再检查匿名请求数量和 OpenAI 用量。
- 怀疑密钥泄漏：立即撤销旧密钥并创建新密钥，不要只修改代码中的变量名。
- 出现大量 429：不要直接提高限制；先确认是真实课堂使用还是自动化滥用。
- 用户报告文本问题：排查时只索取脱敏后的最小复现文本，不要求发送完整私人论文。
